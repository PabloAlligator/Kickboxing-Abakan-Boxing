# Технический отчёт — production revision

## Что было не так в результате Work

1. Админская часть была собрана отдельным монолитным `control/`: один большой route-файл, один большой экран и отдельный набор дублей CSS. Это не соответствовало архитектурному паттерну RioCar/ShumDev.
2. Login был маленькой тёмной карточкой по центру вместо полноценного split-screen интерфейса.
3. В архиве находились `.env` и рабочая SQLite-база. Это production-блокер.
4. Приложенная SQLite-база отставала от последней миграции, поэтому schema/migrations и фактическая БД не совпадали.
5. Технический отчёт утверждал, что данные владельцев не хранятся в `.env`, хотя в исходном архиве были OWNER-переменные.
6. Была лишняя логика управления «командой/админами», хотя продукт предполагает двух равноправных OWNER.
7. Login использовал e-mail, хотя для закрытой системы достаточно отдельного логина.
8. Админские HTML первоначально отдавались без серверной page-защиты и только затем проверяли сессию через JS.
9. Service Worker мог кэшировать защищённые admin-страницы.
10. Public содержал два разных телефона, фиктивный `info@club.ru`, личный Telegram Артёма вместо конфигурируемой ссылки клуба и внешнюю CDN-зависимость Swiper.
11. В HTML была повреждённая ссылка новости.
12. Push персоналки первоначально содержал имя клиента; payload минимизирован.

## Что было сделано хорошо и сохранено

- адекватная предметная Prisma-модель;
- два равноправных OWNER;
- `ownerId` на персональных клиентах и тренировках;
- серверная защита персоналок от IDOR;
- групповые оплаты и расходы отделены от персоналок;
- деньги хранятся целыми копейками;
- `COMPLETED` — единственный статус, который формирует доход персоналки;
- server-side sessions, Argon2, CSRF/origin protection, rate limit, audit log;
- задачи без ответственных;
- динамическое публичное расписание;
- Web Push архитектура.

## Новая схема проекта

- `public/` — публичная часть;
- `admin-pages/` — отдельные защищённые страницы;
- `site/styles/admin/` и `site/scripts/admin/` — UI Control;
- `routes/*.routes.js` — отдельные доменные routes (`athletes`, `groups`, `trainings`, `payments`, `personal`, `tasks`, `expenses`, `statistics`, `settings` и т.д.);
- `middleware/` — auth/CSRF/origin;
- `services/` — sessions/audit/push;
- `config/` — security;
- `prisma/` — schema и единая чистая baseline migration для проекта до первого production deploy.

`control.routes.js` теперь только агрегирует доменные routers.

## Дизайн

Login переработан по композиционному принципу RioCar:

- слева большое фото клуба во всю высоту;
- затемнение/брендинг поверх фото;
- справа светлая отдельная панель формы;
- крупный заголовок;
- поля 58px;
- показать/скрыть пароль;
- loading/error states;
- адаптив для телефона.

Внутренний Control также переведён на RioCar-подобный паттерн: тёмная навигация + светлая рабочая область, но с красным характером «Содружества», а не с визуальной палитрой RioCar.

## Безопасность и privacy

- `.env` и SQLite DB исключены из production archive;
- admin HTML защищён server-side;
- login = `login + password`, публичной регистрации нет;
- аккаунты создаются только CLI-командой `owner:create`;
- endpoints управления пользователями удалены;
- персоналки фильтруются по `req.session.user.id`;
- Service Worker не кэширует `/admin/*` и `/api/*`;
- Push персоналки не содержит имя клиента;
- публичные телефон/Telegram не захардкожены;
- сторонний JS/CSS CDN для Swiper удалён.

## Prisma / БД

Исходная вложенная база не использована, потому что она не соответствовала migration history. Поскольку проект ещё не был production-развёрнут, подготовлена чистая baseline migration, соответствующая текущей schema. Production БД должна создаваться через `prisma migrate deploy`.

## Что проверено в этой ревизии

Проверено статически:

- JS syntax (`node --check`) для backend/frontend/scripts;
- отсутствие старых `/api/control` и `/api/auth` путей;
- отсутствие старой `control/` структуры;
- отсутствие `.env`, production SQLite и `node_modules` в итоговом пакете;
- соответствие baseline migration чистой SQLite-базе;
- server-side ownership логика персоналок;
- разделение общих и личных финансов;
- публичные контакты через server config;
- отсутствие Swiper CDN;
- Service Worker cache policy.

Полный `npm ci`, интеграционный `npm test` и `npm audit` в текущем контейнере выполнить невозможно: npm registry недоступен из среды. Поэтому в отличие от старого отчёта здесь не заявляются вымышленные результаты. Эти три команды обязательны перед реальным production deploy.

## Что нужно заполнить перед деплоем

- `SESSION_SECRET`;
- точный `PUBLIC_PHONE`;
- точный `TELEGRAM_URL`;
- VAPID keys/subject, если включаем Web Push;
- production `DATABASE_URL`;
- два OWNER через `npm run owner:create`.

После этого — `npm ci`, `prisma generate`, `prisma migrate deploy`, `npm run css:min`, tests/audit, PM2, Nginx, SSL.

## Минимальный интерфейс первой очереди

В пользовательском интерфейсе оставлены четыре раздела: Обзор, Спортсмены, Мои персоналки и Настройки. Нумерация и мобильная навигация собраны заново под эти четыре сценария, поэтому интерфейс не выглядит как урезанная версия полной панели. Остальные модули сохранены в кодовой базе для поэтапного включения.
